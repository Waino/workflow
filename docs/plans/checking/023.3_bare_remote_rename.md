# 023.3: Rename the bare remote from `origin` to `bare`

Input: `intent/023_out_of_band`, `planning/023.2_layout_and_vocabulary`
Completeness: complete

## Goal

In oob mode a code repo has a real upstream: `canon/mypackage`'s `origin` (and possibly `upstream`)
point at the collaborative project, while the workflow's own bare clone is a third, private remote.
The workflow tool currently hardcodes `origin` as the name of the bare remote, which would collide.

Rename the workflow-managed remote to `bare` in **both** modes, so `origin` and `upstream` keep their
conventional meanings and there is one remote-naming rule to remember. This is a breaking change for
existing projects, handled by the migration script rather than by compatibility code.

## Scope

In scope: every hardcoded `origin` / `origin/...` reference in the package, remote creation at
`init`, agent clone remote naming, migration step, docs.

Out of scope: multi-repo iteration (023.5) — this plan renames the remote for the single repo per
worktree that exists today, via the 023.2 accessors.

## Design

### Constant

Add `BARE_REMOTE = "bare"` to `workflow/git_helpers.py` and use it everywhere. No literal `"origin"`
may remain in `workflow/` afterwards (grep is the completion criterion). Ref strings become
f-strings: `f"{BARE_REMOTE}/main"`, `f"{BARE_REMOTE}/{branch}"`.

Affected helpers in `git_helpers.py` (~25 sites): `git_push`, `git_fetch`, `git_push_branch`,
`git_ref_exists_remote`, `git_delete_remote_branch`, `git_diff_branch`
(`git diff origin/main...HEAD`), `refresh_main` (including the `fetch origin main:main` and the
`git_remote_url(repo, "origin") is None` guard), `transfer_branch_to_main`, the rebase/force-push
helpers, and every message string mentioning `origin/...`.

### Remote creation

- `_wire_canon_to_bare`: `git remote add bare {bare_path}`, `git push -u bare HEAD`.
- Agent clones: `git clone -o bare bare {agent}` so the clone's remote is named `bare` from the
  start (rather than cloning then renaming).
- `_classify_agent_clone_steps` / `_classify_wire_canon_step`: probe `git_remote_url(repo, BARE_REMOTE)`.
- `_ensure_agent_push_config`: `push.default = current` and `push.autoSetupRemote = true` stay as
  they are, but with a single remote named `bare` they now target `bare` implicitly. Verify
  `git push` with no arguments still resolves: `git_push` passes the remote explicitly, so it does.

### Migration (step 3 in `scripts/migrate_023.py`)

For `bare` plus each worktree in the project: if a remote named `origin` exists and its URL is the
project's bare path, run `git remote rename origin bare`; if a remote named `bare` already exists,
skip. Then, in each worktree, `git fetch bare` and re-point branch upstreams
(`git branch --set-upstream-to=bare/main main`) — otherwise `main` tracks a remote that no longer
exists. Report every action; `--dry-run` prints without executing.

An `origin` whose URL is *not* the bare path is left alone and reported as a warning (in oob-migrated
projects that is a legitimate upstream).

### `doctor`

Report as an anomaly: a worktree with no `bare` remote, or with a remote named `origin` pointing at
the project's bare path (the pre-migration shape). This is the detection that replaces compatibility.
Decision 16 of the intent (agent clones must have exactly one remote, named `bare`) lands in 023.6
together with the rest of the doctor work; keep this plan to the two anomalies above.

## Files touched

- `workflow/git_helpers.py` (constant + all references)
- `workflow/commands/workflow.py` (`_wire_canon_to_bare`, clone commands, classifiers, accept's
  `origin/{branch}` merge ref)
- `workflow/commands/doctor.py` (two anomalies)
- `workflow/tmux_dispatch.py` (comment mentioning `origin/main`)
- `scripts/migrate_023.py` (step 3)
- `docs/source/{workflow,Introduction,caveats}.rst` — wherever `origin` is described
- `docs/example_run_agent_in_docker.sh` — the comment explaining the read-only bare mount says the
  mount path must match "the absolute 'origin' URL recorded at clone time"; update the wording
- tests: `tests/test_git_helpers.py` and every integration test asserting on remote names

## Verification

- `tests/test_git_helpers.py`: assert the argv of `git_push`/`git_fetch`/`git_push_branch` names
  `bare`; `refresh_main` no-ops when no `bare` remote exists.
- Integration: after `init`, canon has exactly one remote named `bare` pointing at `{project}/bare`;
  each agent clone likewise; a full `todo`→`implement`→`check`→`accept` round trip passes.
- Migration: `tests/test_migrate_023.py` case with a project whose worktrees have `origin` → after
  migration each has `bare` and `main` tracks `bare/main`; re-run is a no-op; an unrelated `origin`
  (different URL) is preserved and warned about.
- `doctor` test: pre-migration remote shape → anomaly, exit 1.
- Grep: no `"origin"` literal remains under `workflow/`.

## Risks

1. **Upstream tracking refs.** Renaming a remote moves `refs/remotes/origin/*` to
   `refs/remotes/bare/*` but does not always fix branch `merge`/`remote` config in older git
   versions; the migration must re-set upstreams explicitly and the integration test must cover a
   feature branch with an upstream, not just `main`.
2. **Every project breaks until migrated**, including this repo and any in-flight plan (`019` is
   currently `implementing`). Sequence the merge so the operator migrates immediately afterwards.
3. **`transfer_branch_to_main` / rebase helpers carry `origin` in error messages** that operators
   have learned to read; keep the messages otherwise identical so the recovery instructions still
   match the docs.
4. **Force-push and `git cherry` paths** (`git_helpers.py:449-600`) are the least test-covered
   `origin` users; check each converted site against its existing test rather than trusting grep.

## Dependencies

Requires 023.1 and 023.2 (uses `Layout.bare_repo`). Blocks 023.4.

## Deviations (build)

- The migration renames `origin` in each worktree only, not in `bare` itself: `bare`'s own
  `origin` (if any) points at canon, not at the bare path, so it would be left alone anyway.
- `"origin"` is spelled once, as `git_helpers.LEGACY_BARE_REMOTE`, used by `doctor`'s leftover
  detection and by `scripts/migrate_023.py` (PR-review fix; the grep test exempts only that
  definition).
