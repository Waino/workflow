# 027.1: Prompt dispatch fixes

Input: `intent/027_various_fixes.md` (items 1, 1.1, 1.2, 1.3, 2, 9; doctor audit check)
Completeness: complete

## Goal

`workflow rebase builder/docs/plans/implementing/023.1` was typed into the *planner* window: an
explicitly named agent was silently overridden. The misroute was invisible, and prompts carry
project-relative paths (`builder/docs/plans/...`) that don't match the agent's working directory.
Make routing follow the plan's worktree, make every send say where it went, loudly flag sends to a
window the user isn't looking at, and let `rebase` reach builder without borrowing.

## Scope

In:
- `workflow/tmux_dispatch.py`: routing, borrowing, output, blind-send warning.
- `workflow/models.py`: `Plan.worktree`, `Plan.path_in_worktree`.
- `workflow/stack.py`: `StackEntry.path` convention.
- `workflow/commands/doctor.py`: audit anomaly check.
- `docs/default_config.yaml`: templates and the builder `rebase`.
- User docs and tests.

Out:
- Next step printing and recording for prompts (027.2).
- Whether `resolve_plan` always honours explicitly given fields (separate intent).
- Migrating existing project `config.yaml` files.

## 1. `Plan.worktree` and `Plan.path_in_worktree` (`workflow/models.py`)

Add two properties next to `absolute_path`:

- `worktree -> WorktreeName`: `WorktreeName(self.path.parts[0])`. On an empty path or unknown
  prefix, raise `ValueError` naming the path (the pydantic-free builtin is enough).
- `path_in_worktree -> Path`: `Path(*self.path.parts[1:])`, going through `worktree` so a
  prefix-less path fails the same way.

Replace the hand-rolled `plan.path.parts[0]` parsing with `plan.worktree`:
- `workflow/tmux_dispatch.py` (`_resolve_plan_target`)
- `workflow/state.py` (`transition_plan`)
- `workflow/commands/workflow.py` (around the `worktree_override or WorktreeName(...)` line and the
  `push` repo lookup)
- `workflow/stack.py` (`resolve_stack`): drop the silent canon fallback for "hand-built" paths.
  Tests that construct prefix-less `Plan`s must be fixed to use real worktree paths, not
  accommodated.

## 2. Plan paths in prompts

- `docs/default_config.yaml`: every `{{ plan.path }}` becomes `{{ plan.path_in_worktree }}`.
- `stack_entries` (`workflow/stack.py`) builds `StackEntry.path` from `member.path_in_worktree`.
  Update the `StackEntry.path` docstring to describe the worktree-relative convention.
- `plans_root(worktree)` is `worktree_root/docs/plans` in both modes, so one relative form works
  in-band and oob.

## 3. Routing (`_resolve_plan_target`, `workflow/tmux_dispatch.py`)

After `resolve_plan`, determine the recipient from `plan.worktree`:

1. `canon` → `WorkflowError`: canon has no agent; name an agent worktree explicitly, e.g.
   `planner/<path>`.
2. The recipient agent is the one named like the worktree (agent names equal worktree names).
3. Pick the definition, in order:
   - a target whose `state == plan.state` and `worktree_name == plan.worktree`;
   - otherwise the first target with `worktree_name == plan.worktree` (same agent, another state:
     `ask` on a planning plan uses the intent-state `ask`);
   - otherwise **borrow**: take the first definition's prompt text and render it for the recipient.
     Build the target with `model_copy(update={"agent_name": ..., "worktree_name": ...})` so
     `_git_metadata` reads branch/commit from the recipient's worktree.

The state-first rule also fixes a latent bug: today `critique` on a planning plan matches the
intent-state target first (same worktree) and sends "Critique the idea".

Remove the fallback to `targets[0]`.

Borrowing rules, checked in `_setup_has_plan` (pass `edit_mode` in):
- A definition with a `transition` is never borrowed. Error: `'plan' changes plan state and can
  only be sent to planner (defined in: intent).`
- Without `--edit`: error listing the owning states and agents, e.g.
  `'critique' is not defined for builder (defined in: intent (planner), planning (planner)).
  Re-run with --edit to adapt the prompt for builder.`
- With `--edit`: proceed. The editor opens with the rendered borrowed text.
- A borrowed prompt records no next step (none printed, `next_step=None` in the audit entry).
  The lender's reminder describes the lender's workflow position (e.g. `build` borrowed by
  reviewer would suggest `workflow check`), which doesn't apply to an ad-hoc borrow.
  Decided in the PR review of the 027 stack.

Return a small typed model from `_resolve_plan_target` rather than extending the bare tuple
(e.g. add a `borrowed: bool` field to `_PromptTarget` or return a `_ResolvedTarget` model).

The stack-tip check should use `plan.state` rather than `target.state`, so it holds for borrowed
targets.

## 4. `rebase` for builder (`docs/default_config.yaml`)

- Anchor the prompt text on the first `rebase` definition (`prompt: &rebase_prompt |`).
- Reuse it via `prompt: *rebase_prompt` in `checking`, and in a new `rebase` entry in
  `implementing`.
- Anchor only the text, not the whole mapping, so each state keeps its own `reminder`.
  The builder entry gets `reminder: check`; the others keep `validate`.
- Place the builder entry after `build`, before `check`.
- Also replace the reviewer `rebase` prompt text with a reference to the same anchor.

Add a test that the three `rebase` prompts load as identical strings.

## 5. Dispatch output and blind-send warning

Make `_active_tmux_repo` in `workflow/plan_resolver.py` public (`active_tmux_repo`, updating its
callers and tests). In `_dispatch_prompt`:

- For plan commands, always print `Plan resolved to: <plan.path>` (project-relative, so the
  worktree shows).
- `blind = active_tmux_repo(config.tmux.session_name) != WorktreeName(agent_name)`.
  This is a read-only query, so it runs in dry-run too. No tmux session also counts as blind.
- Pass `blind` to `send_prompt_to_agent`:
  - Dry-run prints `would send to 'planner' [red](Not the active agent in tmux!)[/red]:`
    (suffix only when blind), then the prompt.
  - A real send prints `Sending to 'planner'` with the same suffix before sleeping.
  - When blind, it sleeps `prompt_send_delay` a second time before sending, giving time to Ctrl-C.
- Never rotate the control pane from dispatch.
- Fix the `send_prompt_to_agent` docstring: it doesn't select the window.

## 6. Doctor: impossible audit entries (`workflow/commands/doctor.py`)

Add `_audit_anomalies(config, project_dir) -> list[str]` and print it as its own section via
`_print_anomaly_section`. Flag an entry when:

- its `command` is neither a command in any config state nor a registered script
  (`_SCRIPT_REGISTRY` in `workflow/registry.py`: `start`, `init`, `sync` are logged but aren't in
  states); or
- it's a prompt command with a `transition` whose `actor` isn't the agent of any state defining
  it. That's the class that corrupts the resolver's audit source.

Revised in the PR review of the 027 stack: only the transition-actor case is an anomaly.
Unknown commands go to a separate, non-failing `Audit log notes` section (`_audit_notes`), and only
for entries whose `input_plan` is an active plan (not done/rejected, not missing, not stateless).
The log is append-only, so renaming a command in `config.yaml` would otherwise fail doctor forever.
A transition prompt in a state with `agent: null` is nonsensical, so flagging all its entries is fine.

Borrowed non-transition prompts are legitimate and not flagged. Message format:
`<timestamp> <actor> <command> <input_plan>: <reason>`. `read_audit_log` returns no line numbers,
and extending it just for this isn't worth it.

## Verification

Unit tests:
- `Plan.worktree` and `path_in_worktree`, parametrized over in-band, oob-like and hierarchical
  paths. A prefix-less path raises.
- Routing with a real config and tmp filesystem (see existing `tests/test_cli.py` dry-run prompt
  tests for the pattern):
  - `rebase builder/.../implementing/023.1` goes to builder using the implementing definition.
  - `critique planner/.../planning/x` uses the planning-state text.
  - `critique builder/...` without `--edit` exits 1 with the owning-states message.
  - With `--edit` (`EDITOR` set to `true`), it's sent to builder.
  - `plan builder/...` is refused even with `--edit`.
  - A plan resolving to canon is an error.
  - The rendered prompt contains `docs/plans/...`, not `builder/docs/plans/...`.
- Blind warning: patch `active_tmux_repo`. The suffix appears only when the active window
  differs, and the extra sleep only happens for blind real sends (patch `time.sleep`, count calls).
- Doctor: synthetic audit logs with an unknown command, a `plan` entry by builder, and a borrowed
  `critique` by builder (not flagged).
- `stack_entries` paths are worktree-relative.

End-to-end: `workflow --dry-run rebase builder/docs/plans/implementing/<plan>` in a sandbox project
shows `Plan resolved to: builder/...` and `would send to 'builder'`.

## Risks

- Removing the canon fallback in `resolve_stack` may surface tests (or real call sites) that build
  `Plan`s with prefix-less paths. Fix the callers; don't reintroduce a fallback.
- `blind` in dry-run depends on the live tmux state of the machine running the tests. Always patch
  `active_tmux_repo` in tests that assert on dispatch output.
- Project configs copied from the old default keep `{{ plan.path }}`. That still works, just with
  the prefix, so no migration is needed.
- Adding `rebase` to `implementing` changes the generated AGENTS.md section. Projects that adopt
  the new default must re-run `workflow agents_md`.

## Dependencies

None.

## Clarifications (builder Q&A)

- Canon-resolved plans (todo/done/rejected without an explicit agent worktree) are an error; no auto-routing.
  An explicit `planner/.../todo/042_foo` routes to planner via the "first target in that worktree" rule.
- The blind-send warning (suffix, extra sleep) applies to every prompt dispatch, including stateless commands.
  Only the `Plan resolved to:` line is plan-only.
- Recipient and `blind` use `WorktreeName(agent_name)` directly (agent names equal worktree names).
