# 004.1: CLI Framework and Script Registry

Input: `intent/001_idea`, subdivided from `planning/004_cli_framework`

## Goal

Build the foundational CLI skeleton: the Click entry point, dry-run and config
global options, the script registry that links config entries to Python functions,
and the `run_command` shell helper. This is the layer that all script commands
plug into. Prompt dispatch and audit logging are handled in 004.2 and 004.3.

## Scope

- Click CLI group with `--dry-run` and `--config` global options
- Script registry (`register_script` decorator, `validate_registry`)
- `run_command` shell helper respecting dry-run mode
- `ConfigError` exception type
- Wiring prompt commands in at startup (calls into 004.2 once that is implemented)

## CLI structure

The Click entry point is a group named `main` (matching the existing `pyproject.toml`
entry point `workflow = "workflow:main"`).  `validate_registry` is not called explicitly
here; it is handled by `WorkflowConfig.validate_script_references` during `load_config`.

```python
@click.group()
@click.option("--dry-run", is_flag=True, help="Print commands without executing them.")
@click.option("--config", "config_path", type=click.Path(exists=True), help="Path to config file.")
@click.pass_context
def main(ctx: click.Context, dry_run: bool, config_path: str | None) -> None:
    """Agentic workflow orchestration tool."""
    config = load_config(Path(config_path) if config_path else None)
    register_prompt_commands(main, config)  # wired in by plan 004.2
    ctx.ensure_object(dict)
    ctx.obj["config"] = config
    ctx.obj["dry_run"] = dry_run
```

Whether `config.project_dir is None` (i.e. running outside a project root) is checked
by each individual command, not in the group callback.

The call to `register_prompt_commands` is imported from `workflow/tmux_dispatch.py`
(plan 004.2). Until 004.2 is implemented, provide a no-op stub in `tmux_dispatch.py`
so that `cli.py` can import it without error:

```python
# tmux_dispatch.py stub — replaced by plan 004.2
def register_prompt_commands(cli: click.Group, config: WorkflowConfig) -> None:
    pass
```

## Script registry

`ConfigError` and `register_script` live in `workflow/registry.py`.
`validate_registry` is **not** a standalone function; the validation is wired into the
existing `WorkflowConfig.validate_script_references` model validator in `config.py`
(currently a no-op stub).  The validator lazy-imports `_SCRIPT_REGISTRY` from
`registry.py` at call time, which avoids a circular import.

```python
class ConfigError(Exception):
    """Raised when the config is invalid (e.g. references an unknown script)."""

_SCRIPT_REGISTRY: dict[str, ScriptFunc] = {}

ScriptFunc = Callable[..., int]  # return code

def register_script(name: str) -> Callable[[ScriptFunc], ScriptFunc]:
    """Decorator to register a Python function as a named script."""
    def decorator(func: ScriptFunc) -> ScriptFunc:
        _SCRIPT_REGISTRY[name] = func
        return func
    return decorator
```

Updated `WorkflowConfig.validate_script_references` in `config.py`:

```python
@model_validator(mode="after")
def validate_script_references(self) -> WorkflowConfig:
    from workflow.registry import _SCRIPT_REGISTRY, ConfigError  # lazy — avoids circular import
    for state_config in self.states.values():
        for cmd in state_config.commands:
            if isinstance(cmd, ScriptCommand) and cmd.script not in _SCRIPT_REGISTRY:
                raise ConfigError(f"Config references unknown script: {cmd.script!r}")
    return self
```

Because the validator runs during `WorkflowConfig` construction (inside `load_config`),
all script command modules must be imported **before** `load_config` is called.
Use a conventional block of imports at the top of `cli.py`:

```python
import workflow.commands.info      # noqa: F401  — registers info commands
import workflow.commands.workflow  # noqa: F401  — registers workflow commands
```

Each module contains placeholder functions for their respective commands.
`workflow.commands.info` contains `status`, `log`, and `cheat`.
`workflow.commands.workflow` contains all other script commands
(`todo`, `implement`, `doublecheck`, `push`, `accept`, `reject`, `new`, `init`, `start`,
`claude.md`).
The placeholder functions will be fleshed out in later plans.

## Shell command execution

```python
def run_command(
    args: list[str],
    *,
    dry_run: bool = False,
    **kwargs: Any,
) -> subprocess.CompletedProcess[bytes] | None:
    """Run a shell command, or print it if dry_run is True.

    Passes **kwargs through to subprocess.run (e.g. cwd, env, capture_output).
    Raises subprocess.CalledProcessError on non-zero exit (check=True).
    """
    if dry_run:
        console.print(f"[dim]would run:[/dim] {shlex.join(args)}")
        return None
    return subprocess.run(args, check=True, **kwargs)
```

## Risks

- All command modules must be imported before `load_config` is called at CLI startup
  (the model validator runs during construction).  A missing import silently skips
  validation for that module.  Keep the import block in `cli.py` complete and documented.
- Tests that construct `WorkflowConfig` with `script`-type commands must import the
  command modules first, so the registry is populated.  Add the imports to relevant test
  files as part of this plan.
- Until 004.2 is wired in, `register_prompt_commands` is a no-op stub.
  This is intentional; prompt commands simply won't appear in `--help` until 004.2
  is implemented. Do not try to call tmux before 004.2 is ready.
