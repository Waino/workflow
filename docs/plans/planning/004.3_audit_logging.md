# 004.3: Audit Logging

Input: `intent/001_idea`, subdivided from `planning/004_cli_framework`

## Goal

Implement the single-file JSONL audit log: write one entry per CLI invocation and
provide a reader for `workflow log` and free-number calculation. Both script commands
(plan 004.1 territory) and prompt dispatch (plan 004.2) call into this module, so it
has no dependencies on either and can be implemented first.

## Scope

- `write_audit_log`: append a single `AuditLogEntry` to `workflow.log.jsonl`
- `read_audit_log`: read and parse all entries, sorted by timestamp
- Log file location convention and `.gitignore` note

## Log file location

```
{project_dir}/workflow.log.jsonl
```

Alongside `.workflow_root`, outside all git repos. Never committed.
Add to `.gitignore` in the project root (or note in `workflow init` that it should be).

## Writing

```python
def write_audit_log(project_dir: Path, entry: AuditLogEntry) -> None:
    """Append one entry to the JSONL audit log.

    Creates the file if it does not exist.
    Each line is a complete JSON object terminated by a newline.
    """
    log_path = project_dir / "workflow.log.jsonl"
    with log_path.open("a", encoding="utf-8") as f:
        f.write(entry.model_dump_json() + "\n")
```

`AuditLogEntry` fields (from plan 002):
- `timestamp`: set by the caller to `datetime.now(UTC)` at the moment of dispatch
- `actor`: `"human"` for script commands; agent name for prompt dispatch
- `command`: the command name (e.g. `"critique"`, `"implement"`)
- `input_plan`: canonical plan name string, or `None`
- `output_plans`: list of output plan name strings (e.g. for `subdivide`)

Sorting by timestamp ensures chronological order even if entries were written
out of order (e.g. clock skew, manual edits). Use `AuditLogEntry.model_validate_json`
for each line; catch `ValidationError` and `JSONDecodeError` and emit a Rich warning
with the line number before continuing.

## Risks

- The log file is append-only and not under version control, so concurrent writes from
  multiple CLI invocations could interleave. Since only one human operator runs the CLI
  this is not a practical concern, but noted for completeness.
- A completely corrupted log file (e.g. binary garbage) should not crash `workflow log`
  or free-number calculation. The skip-and-warn approach in `read_audit_log` handles this.
