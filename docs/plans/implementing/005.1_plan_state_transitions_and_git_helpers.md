## Plan state transitions

All paths below are relative to `project_dir`.

`plan.path` is stored relative to `project_dir`, e.g. `planner/docs/plans/planning/005_foo.md`.
The leading path component is the repo name.

`repo_override` replaces that leading component when the transition must be performed in a
different repo than the one recorded in the plan (in practice always `"master"`, because
plans are pushed and pulled to `master` immediately before the transition).
If `repo_override` is `None`, the repo is taken from `plan.path` directly.

```python
def transition_plan(
    plan: Plan,
    target_state: PlanState,
    project_dir: Path,
    repo_override: str | None = None,
    *,
    dry_run: bool = False,
) -> Plan:
    """Move a plan file from its current state subdirectory to the target state subdirectory.

    Uses `git mv` so the rename is tracked by git.
    Returns a new Plan object with the updated state and path (still relative to project_dir).
    Does NOT commit — the caller is responsible for committing.
    """
    repo_name = repo_override if repo_override is not None else plan.path.parts[0]
    repo_path = project_dir / repo_name
    source = project_dir / plan.path
    target_dir = repo_path / "docs" / "plans" / target_state.value
    if not dry_run:
        target_dir.mkdir(parents=True, exist_ok=True)
    target = target_dir / plan.path.name
    git_mv(repo_path, source, target, dry_run=dry_run)
    new_path = Path(repo_name) / "docs" / "plans" / target_state.value / plan.path.name
    return plan.model_copy(update={"state": target_state, "path": new_path})
```

## Git helpers

Thin wrappers around git commands, all respecting dry-run mode.

```python
def git_pull(repo_dir: Path, *, dry_run: bool = False) -> None:
    """Pull from the bare repo."""

def git_push(repo_dir: Path, *, dry_run: bool = False) -> None:
    """Push to the bare repo."""

def git_fetch(repo_dir: Path, *, dry_run: bool = False) -> None:
    """Fetch from the bare repo."""

def git_merge(repo_dir: Path, branch: str, *, dry_run: bool = False) -> None:
    """Merge a branch into the current branch."""

def git_checkout(repo_dir: Path, branch: str, *, create: bool = False, dry_run: bool = False) -> None:
    """Checkout a branch, optionally creating it."""

def git_commit(repo_dir: Path, message: str, *, dry_run: bool = False) -> None:
    """Stage all tracked changes (git add -u) and commit."""

def git_current_branch(repo_dir: Path) -> str:
    """Return the name of the current branch."""

def git_commit_hash(repo_dir: Path, short: bool = True) -> str:
    """Return the current commit hash."""

def git_mv(repo_dir: Path, source: Path, target: Path, *, dry_run: bool = False) -> None:
    """Move or rename a file and stage the change with git.

    source and target may be absolute paths; git is invoked with cwd=repo_dir.
    """
```

These all delegate to `run_command` from plan 004.1. The remote is always named `origin`.

## Push-pull-merge sequence

Several commands (todo, implement, accept) share a common git sequence.
Extract as a reusable helper:

```python
def transfer_branch_to_main(
    source_repo: Path,
    master_repo: Path,
    bare_repo: Path,
    *,
    dry_run: bool = False,
) -> None:
    """Push from source agent repo to bare, pull to master, merge to main, push back.

    Reads the current branch from source_repo; raises WorkflowError if it is 'main'.

    1. git push (source_repo → bare)
    2. git pull (master ← bare)
    3. git merge <branch> (in master)
    4. git push (master → bare)
    """
```
