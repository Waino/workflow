# 027.3: Conservative test parametrization

Input: `intent/027_various_fixes.md` (item 8)
Completeness: complete

## Goal

Several test groups repeat the same body with different literals. Fold the worst of them into
`pytest.mark.parametrize` so adding a case is one line and the intent of each group is visible at
a glance, without losing coverage.

## Scope

In: exactly the groups listed below.

Out:
- Every other test.
- Behaviour changes.
- Test helper refactors beyond what a listed group needs.
- Test files touched by 027.1/027.2 for new tests, beyond the listed groups.

The selection was made by an AST scan for structurally identical test bodies plus a manual read of
the largest files. Groups whose members differ in setup steps (not just literals) were left alone.

## Rules

- No coverage drop: compare `pytest --cov=workflow --cov-report term` totals before and after
  (`pytest-cov` is already configured in `pyproject.toml`).
- Every removed assertion must have a parametrized equivalent. Where members of a group assert
  extra fields, keep those fields in the parameter tuple (use `None` for "not asserted" only if
  the original didn't assert it).
- Use `pytest.param(..., id="...")` with ids derived from the old test names, so failures stay
  readable.
- Keep error-path tests separate from happy-path tests. Make one parametrized test per shape.
- One commit per file.

## Groups

### `tests/test_plan_resolver.py`

1. `TestParsePlanFilename`: `test_simple`, `test_slug_with_underscores`,
   `test_hierarchical_sequence_number`, `test_zero_padded_sequence_number` → one test over
   `(filename, seq, slug)`. `test_missing_underscore_raises` stays.
2. `TestParseReviewFilename`: the four valid cases (`critique_simple`,
   `critique_slug_with_underscores`, `pr_simple`, `pr_slug_with_underscores`) → one test over
   `(stem, sub_state, seq, slug, ts, commit)`. The three `*_raises` → one test over
   `(stem, sub_state, match)`.
3. `TestResolvePlan` fuzzy name forms: `test_seq_only`, `test_name_only`,
   `test_name_with_md_suffix`, `test_state_and_name`, `test_state_and_seq`,
   `test_docs_plans_prefix`, `test_repo_prefix_in_path`, `test_hierarchical_seq` → one test over
   `(repo, state, filename, reference, expected_slug, expected_state, expected_seq)`, keeping each
   original assertion.
4. `TestParseGitLogOutput`: the four state-returning cases → one test over `(output, state)`. The
   rename case also asserts the timestamp, so keep `timestamp` in the tuple for all four. The two
   `None` cases → one test over `output` (including both whitespace variants of
   `test_empty_output_returns_none`).
5. `TestTmuxSource`: the five server-mock cases → one test over `(alive, window_name, expected)`,
   where `window_name=None` means "session not found". The two exception cases → one test over the
   raised exception.

### `tests/test_models.py`

6. `TestReview`: `test_pr_review_requires_commit`, `test_critique_review_requires_timestamp`,
   `test_full_review_requires_timestamp`, `test_full_review_requires_commit`,
   `test_review_rejects_non_review_state` → one test over `(kwargs, match)`.
   `test_full_review_valid` and `test_full_review_name` share an identical constructor: extract a
   `_full()` helper like the existing `_pr()`/`_critique()`.

### `tests/test_git_helpers.py`

7. `resolve_default_branch`: `prefers_origin_head`, `falls_back_to_main`,
   `falls_back_to_master`, `keeps_slashes_in_branch_name` → one test over
   `(upstream_branch, delete_origin_head, expected)`. `raises_when_unresolvable` and
   `of_bare_remote` stay.
8. `git_is_valid_repo`: `false_for_non_repo` and `false_for_missing_dir` → one test over
   `(mkdir,)`. The true-cases differ in setup and stay.

### `tests/test_workflow_commands.py`

9. `log` filters: `test_log_filter_by_agent`, `_by_command`, `_by_since`, `_by_until`,
   `_by_plan_substring` → one test over `(args, present, absent)`, where `present` and `absent` are
   tuples of substrings. Keep the inline comments as `pytest.param` ids or comments.

### `tests/test_agents_md.py`

10. `normalise`: `strips_trailing_whitespace`, `converts_crlf`, `adds_trailing_newline`,
    `drops_trailing_blank_lines` → one test over `(text, expected)`. `test_normalise_idempotent`
    stays.

### `tests/test_stack.py`

11. `find_stack_member`: `matches_canonical_name`, `matches_padded_or_unpadded_sequence_number`,
    `matches_unpadded_hierarchical_sequence_number`, `normalizes_reference_forms` → one test over
    `(filename, reference)`. Merge the existing parametrize lists into it.

## Verification

- `pytest` passes, and the collected test count doesn't drop (parametrized cases count
  individually).
- Coverage is unchanged or higher (see Rules).
- `mypy` passes and `black` is clean (pre-commit hook).

## Risks

- Merging tests can silently weaken them. Review each diff for assertions that vanished from one
  member.
- Conflicts with 027.1/027.2 test edits (notably `test_stack.py` and `test_plan_resolver.py`).
  Build this plan last, on top of both.

## Dependencies

- 027.1 and 027.2 (merge-order only, to avoid test conflicts).
