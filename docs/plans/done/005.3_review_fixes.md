# 005.3: Review fixes for plan state and git helpers

Input: `docs/plans/reviews/pr/005_plan_state_and_git_3b56c73.md`

## Goal

Fix the workflow-blocking issues identified in the PR review for 005 so that
`workflow doublecheck` resolves plans in the correct repo, `transition_plan()`
supports master-side transitions correctly, diff-related failures are surfaced as
friendly command errors, and the new modules gain focused test coverage.

Also fix the existing typing issues in the tests so the pre-commit hook can run
`mypy workflow tests` instead of only `mypy workflow`.

## Scope

- Repo-aware plan resolution for `workflow doublecheck`
- Correct `repo_override` semantics in `transition_plan()`
- Normalize diff failures into `WorkflowError`
- Add direct tests for `state.py`, `git_helpers.py`, and `doublecheck.py`
- Extend CLI tests for `workflow doublecheck`
- Fix test typing issues and update `.git-pre-commit-hook`

## Problem summary

The current branch has five concrete gaps:

1. `workflow doublecheck` resolves plans with `resolve_plan(..., project_dir)` and
   therefore searches only `master`, which breaks the normal `planning` and
   `checking` workflows.
2. `transition_plan(..., repo_override="master")` only overrides the destination
   repo. The source path still points at the original repo recorded in `plan.path`.
3. `doublecheck()` wraps fetch failures, but raw `CalledProcessError` can still
   escape from later `git diff origin/main...HEAD` calls.
4. The new modules are barely exercised by tests, so the two workflow bugs above
   were not caught.
5. The test suite still has typing issues, so the hook only runs `mypy workflow`.

## Design overview

### 1. Repo-aware plan resolution for `workflow doublecheck`

Keep the fix scoped to the `doublecheck` script command. Add a helper in
`workflow/commands/workflow.py` that resolves a plan across the repos/states where
the `doublecheck` script is configured.

Core shape:

```python
def _resolve_doublecheck_plan(config: WorkflowConfig, plan_path: str) -> Plan: ...
```

Implementation outline:

- Inspect `config.states` and collect every state whose command list contains the
  script target `doublecheck`.
- For each candidate state, derive the repo to search from that state's configured
  agent (`planner` / `reviewer`) or `master` when the state has no agent.
- Call `resolve_plan(plan_path, config.project_dir, expected_states=[state], repo=repo)`
  for each candidate, using the same candidate-resolution pattern already used in
  `tmux_dispatch.py`.
- If exactly one candidate resolves, use it.
- If none resolve, raise the most useful `PlanNotFoundError`.
- If multiple candidates resolve, raise `AmbiguousPlanError`.

This keeps loose path parsing intact while removing the incorrect implicit
`master` fallback.

### 2. Correct `repo_override` handling in `transition_plan()`

When `repo_override` is present, rewrite the leading repo component of the source
path as well as the destination path.

Core shape:

```python
def _replace_repo_prefix(path: Path, repo_name: str) -> Path: ...
```

Implementation outline:

- Treat `plan.path` as a project-relative path whose first component is always the
  repo name.
- Compute `source_rel` from `plan.path`, replacing the first component when
  `repo_override` is provided.
- Build `source = project_dir / source_rel`.
- Build the target path in the same repo, under `docs/plans/{target_state.value}/`.
- Return a copied `Plan` whose `path` points at the overridden repo.

This matches the intended `todo` / `implement` / `accept` / `reject` flow, where
the transitioned file is the copy already present in `master`.

### 3. Normalize diff failures once, not in every check

Refactor `doublecheck()` so it shells out for branch diffs in one place, then passes
the decoded diff data into the individual checks.

Core shape:

```python
full_diff = _read_branch_diff(repo_path)
changed_files = _read_branch_diff(repo_path, "--name-only").splitlines()
```

Implementation outline:

- Add a private helper in `workflow/doublecheck.py` that wraps `git_diff_branch()`
  and converts `CalledProcessError` into `WorkflowError` with repo context.
- Fetch once, then read:
  - full diff text for `noqa-nosec`
  - changed file list for `file-scope` and `claude-md`
- Update the individual check helpers to accept precomputed diff data instead of
  calling git themselves.

This improves both error handling and efficiency.

### 4. Test coverage to add

Add direct tests instead of relying on incidental coverage from other modules.

#### `tests/test_state.py`

- `transition_plan()` without `repo_override`
- `transition_plan()` with `repo_override="master"`
- Assert the exact `git_mv()` source/target paths and returned `Plan.path`

#### `tests/test_git_helpers.py`

- `transfer_branch_to_main()` calls helpers in the expected order
- it raises `WorkflowError` when `git_current_branch()` returns `main`

#### `tests/test_doublecheck.py`

- `infer_target_repo()` for planning/checking/master-style states
- file-scope allow/deny behavior for planner, builder, reviewer, master
- `noqa-nosec` detection on added diff lines only
- git hook success/failure cases with real temp symlinks/files
- CLAUDE hash success/failure cases
- fetch failure and diff failure are surfaced as `WorkflowError`

#### `tests/test_cli.py`

- `workflow --dry-run doublecheck 005` resolves a plan found only in `planner`
- `workflow --dry-run doublecheck 005` resolves a plan found only in `reviewer`
- normal-mode `doublecheck` prints results and next-step guidance when
  `run_doublecheck()` is monkeypatched to return pass/warn results

### 5. Fix test typing and then widen the hook

Fix the existing test typing issue directly instead of weakening typing.

Implementation outline:

- Update `tests/test_cli.py` so the fake audit callback accepts the real
  `AuditLogEntry` type (or a narrow protocol if that proves cleaner).
- Keep new tests fully annotated and avoid `object` when the callback contract is
  known.
- Run `mypy workflow tests` until it is clean.
- Only then update `.git-pre-commit-hook` from:
  - `mypy workflow`
  - to `mypy workflow tests`

## File organization

- `workflow/commands/workflow.py` — repo-aware `doublecheck` plan resolution
- `workflow/state.py` — source/destination repo override fix
- `workflow/doublecheck.py` — centralized diff loading and error normalization
- `tests/test_state.py` — new transition helper tests
- `tests/test_git_helpers.py` — new git helper tests
- `tests/test_doublecheck.py` — new doublecheck tests
- `tests/test_cli.py` — CLI coverage + typing fix
- `.git-pre-commit-hook` — run `mypy workflow tests`

## Dependencies

- Existing 005 implementation on this branch
- `resolve_plan()` behavior from plan 003
- The review findings in `docs/plans/reviews/pr/005_plan_state_and_git_3b56c73.md`

## Risks

- The config-driven resolver for `doublecheck` must stay simple: do not generalize
  prematurely into a full script-target framework unless the edit actually needs it.
- The new tests should avoid real networked git remotes; use monkeypatching and temp
  directories for deterministic coverage.
- Refactoring diff handling must preserve current check semantics while improving the
  error path.
- Update the pre-commit hook only after `mypy workflow tests` is confirmed green.
